# CONSTITUTIONAL RUNTIME
Version: 1.2.0
Status: Canonical

---

# Purpose

The Constitutional Runtime governs every mutation of authoritative state.

It transforms the constitution from documentation into an executable governance system.

No mutation bypasses the runtime.

---

# Runtime Responsibilities

The runtime shall:

- validate authority
- validate schema
- validate semantic integrity
- validate dependencies
- validate policies
- validate constitutional rules
- compute impact
- propagate consequences
- regenerate projections
- verify replay
- record evidence
- record receipts
- emit findings
- preserve lineage
- preserve provenance
- preserve history
- reject invalid mutations
- maintain deterministic convergence

---

# Runtime Pipeline

Every mutation executes the following stages.

## Stage 1

Receive mutation.

---

## Stage 2

Resolve governing authority.

---

## Stage 3

Verify authority digest.

---

## Stage 4

Validate schema.

---

## Stage 5

Validate constitutional policy.

---

## Stage 6

Perform semantic analysis.

Detect:

- duplicates
- ambiguity
- contradiction
- supersession
- invalid terminology
- missing relationships

---

## Stage 7

Dependency analysis.

Compute:

- upstream impact
- downstream impact
- affected projections
- affected validators
- affected runtime artifacts

---

## Stage 8

Task analysis.

Automatically determine:

- newly complete tasks
- reopened tasks
- blocked tasks
- unreachable tasks
- obsolete tasks
- merged tasks
- superseded tasks

Task state is always derived.

Never manually maintained.

---

## Stage 9

Propagation.

Continue until:

- no additional changes occur
- deterministic fixed point reached

Fail on:

- cycles
- oscillation
- infinite propagation
- conflicting outcomes

---

## Stage 10

Regenerate projections.

Including:

- markdown
- codex projections
- ChatGPT projections
- manifests
- indexes
- queues
- reports
- dashboards
- integrity trees

---

## Stage 11

Replay verification.

Entire graph must replay successfully.

---

## Stage 12

Benchmark.

Compare against previous accepted state.

Reject unexplained regression.

---

## Stage 13

Record:

- evidence
- receipts
- findings
- benchmark
- validator outputs
- replay outputs
- integrity results

---

## Stage 14

Commit authoritative mutation.

---

# Automatic Completion

Tasks may complete automatically only when supported by evidence.

Completion never originates from user interface state.

Completion requires constitutional acceptance criteria.

---

# Automatic Reopening

Completed tasks reopen automatically when:

- evidence becomes invalid
- dependency changes
- validator fails
- replay fails
- authority changes
- contradiction discovered

Historical completion remains immutable.

---

# Automatic Prioritization

Priority is continuously recomputed.

Factors include:

- authority
- blockers
- dependency depth
- constitutional importance
- replay risk
- architectural impact
- implementation cost
- recovery cost
- execution readiness

The runtime shall never:

- invent authority

- delete accepted history

- accept unconstitutional mutation
- manufacture evidence
- bypass replay
- bypass validation
- bypass policy
