# AD-20260923-001 — Glyph Atomic Programming Level

Status: accepted
Accepted: 2026-09-23
Authority: current user directive
Scope: Savant programming composition
Implementation state: authority accepted; propagation pending
Supersedes:
- `character` as the atomic programming-edifice level wherever asserted by earlier Savant programming-composition authority
- conflicting atomic-level terminology in current programming-composition canon

## 1. Decision

The canonical atomic level of Savant programming composition is `glyph`.

The canonical ascending programming edifice is:

```text
glyph
→ line
→ segment
→ snippet
→ script
→ engine
→ subsystem
→ system
→ application
```

The programming edifice contains exactly nine levels and eight adjacent inter-level transitions.

## 2. Atomic invariant

`glyph` is the atomic programming-edifice level.

A glyph is the smallest canonical textual or symbolic source unit represented by the Savant programming composition graph.

No programming-edifice level exists beneath glyph.

Higher programming substance emerges by composition from glyph instances.

Canonical glyph substance exists once and is reused by reference wherever possible.

## 3. Character compatibility

`character` is no longer a canonical Savant programming-edifice level.

Historical accepted decisions and historical records using `character` remain unchanged as immutable history.

The term `character` may remain valid where required by:

- a programming language;
- an external specification;
- an encoding;
- a compatibility surface;
- historical evidence;
- ordinary textual description that does not claim Savant edifice authority.

Such uses do not create or restore a `character` programming-edifice level.

Where an earlier Savant authority uses `character` specifically to mean the atomic programming-edifice level, current interpretation is `glyph`.

## 4. Composition law

Canonical programming composition is:

- glyph instances compose lines;
- line instances compose segments;
- segment instances compose snippets;
- snippet instances compose scripts;
- script instances compose engines;
- engine instances compose subsystems;
- subsystem instances compose systems;
- system instances compose applications.

Every non-atomic level emerges through ordered composition of instances of the immediately preceding level.

Higher structures reference their constituents rather than duplicating constituent substance.

## 5. Instance law

Every stable reusable programming element may be represented as an instance.

Every programming instance remains:

- graph-addressable;
- recursively composable;
- independently reusable where its semantics permit;
- lineage-preserving;
- provenance-preserving;
- dependency-exposing;
- compatible with typed Segues;
- extensible without architectural replacement.

A directory is not inherently an instance.

A file is not inherently an instance.

A projection is not inherently an instance.

Canonical substance exists once.

## 6. Segue law

The canonical adjacent programming transitions are:

```text
glyph → line
line → segment
segment → snippet
snippet → script
script → engine
engine → subsystem
subsystem → system
system → application
```

These eight transitions may be represented through typed Segues under existing Segue law.

A Segue references its endpoints and does not duplicate endpoint substance.

Not every syntactic adjacency requires a materialized Segue. A transition becomes a stable Segue instance only where its semantics require identity, reuse, policy, validation, compatibility, observation, extension, or governance.

## 7. Projection law

Source-code projections must remain deterministically reconstructible from authoritative programming composition where that authority has been substantiated.

The canonical lower projection chain is:

```text
glyph instances
→ line instances
→ segment instances
→ snippet instances
→ typed segues
→ script instance
```

Higher programming projections recursively continue:

```text
script instances
→ engine instances
→ subsystem instances
→ system instances
→ application instances
```

Projected files may be deleted and regenerated without deleting their authoritative source instances.

Filesystem layout alone does not establish composition authority.

Unknown composition boundaries remain unresolved rather than inferred from paths.

## 8. Measurement law

When Savant measures programming-substance deduplication:

- glyph is the atomic measurement level;
- canonical substance and instance/reference representation are measured separately;
- zero duplicated substantive bytes must not be represented as literal zero physical storage;
- reference, identity, lineage, provenance, relationship, and projection overhead remains representation cost;
- hypothetical higher-level savings must not be reported as measured until the corresponding composition instances are substantiated.

Historical measurements using the label `character` remain historical evidence and may be reinterpreted as glyph-level measurements only when their measurement semantics are otherwise identical.
