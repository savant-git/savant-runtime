# Phase 8 — Constitutional Runtime Convergence

The constitutional catalog is the semantic source of truth. Runtime services retain no
independent definitions of identity, authority, lineage, provenance, relationships,
dependencies, schemas, or metadata. They query the immutable semantic registry through
the universal resolver and regenerate projections from registered objects.

## Model

- Registration occurs once per canonical identity and rejects replacement.
- Authority is effective data reconstructed along object → lineage → doctrine →
  constitution → reality ancestry. Consumers do not supply overrides.
- Lineage, provenance, dependency closure, reflection, graphs, and documentation are
  derived views. Their engines store no semantic state.
- Projection providers cover runtime, documentation, Markdown, JSON, graph,
  visualization, and future UI/API/IDE/tooling surfaces. Providers are pure.
- The projection cache is disposable. Constitutional digests key entries, and schema,
  authority, version, lineage, provenance, or relationship changes invalidate it.

## Reflection and extension

Reflection answers identity, purpose, declaration, governance, creation, schema,
dependency, supersession, projection, documentation, implementation, and graph questions
as deterministic structured data. New consumers should add a projection provider or use
the resolver; they must not introduce a parallel registry. Existing registry APIs remain
compatibility delegates.

## Migration

`convergence_report` inventories repeated semantic values, projection opportunities,
runtime adapter coverage, and remaining legacy systems. `convergence_report_markdown`
emits the same evidence for review. Migration remains additive and reversible: existing
authority files are unchanged, runtime discovery continues to produce immutable adapters,
and validation checks identity, schema, authority, lineage, provenance, relationship,
dependency, projection, registry, and graph integrity.
