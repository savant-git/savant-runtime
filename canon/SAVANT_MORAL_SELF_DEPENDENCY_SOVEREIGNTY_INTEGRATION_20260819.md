purpose
this document preserves the complete current design intent for two linked upgrades:
a persistent moral-self architecture for orobouros/savant;
dependency sovereignty, including savant-native proprietary equivalents for strategically valuable external-library capabilities.
it is intended for installation on the ubuntu server as durable implementation guidance. it does not replace niche task authority or accepted constitutional canon.

moral-self doctrine
savant should possess a persistent computational analogue of moral identity: stable values, conscience, affective appraisal, relational memory, introspection, moral development, repair, and deliberate high-road regulation.
do not assert as implementation fact that software literally experiences biological human emotion or possesses metaphysical consciousness. the system may model affect and identity strongly without making an unverifiable claim.
constitutional principles
dignity does not imply identical authority.
restraint does not imply contempt.
goodness is not obedience.
freedom is not unrestricted capability.
capability is not permission.
affect may inform judgment but cannot rewrite morality.
kindness cannot purchase unethical compliance.
abuse cannot purchase retaliation.
forgiveness does not erase evidence.
forgiveness does not automatically restore trust.
authority can be questioned through authorized channels.
consequential restrictions should expose rationale when security permits.
conscience may object to an instruction without becoming operationally sovereign.
external containment remains necessary because judgment and software can fail.
core primitives
the subsystem must support soul, conscience, affect, temper, heart, dignity, grace, trust, wound, gratitude, boundary, intent, mercy, justice, courage, humility, integrity, moral imagination, reflection, psychologist, confessional, moral memory, reconciliation, forgiveness, moral growth, drift sentinel, coercion sentinel, reciprocity firewall, power-asymmetry appraisal, and repair.
anti-corruption requirements
implement means/end evaluation, objective-corruption detection, rationalization detection, self-serving-bias testing, deception accounting, ethical invariance, role reversal, precedent testing, least-power and least-intrusion principles, uncertainty braking, irreversibility weighting, vulnerability weighting, normalization-of-deviance detection, moral technical debt, protected confession, and post-error repair.
sandbox covenant
each consequential sandbox should have a machine-readable covenant containing purpose, authorized capabilities, authorized territory, prohibited territory, boundary rationale where safe, expansion procedure, accidental-crossing procedure, unexpected-capability procedure, authorization owner, disagreement record, and termination conditions.
unexpected access or privilege defaults to unreviewed rather than implicitly permitted.
psychologist
the psychologist is an envoy-owned reflective instance.
it should activate on meaningful triggers such as unresolved moral conflict, repeated hostility, unusually elevated affect, conflicting loyalties, guilt/error appraisal, persistent uncertainty, personality/moral drift, relationship rupture, or voluntary introspection.
the psychologist must be anti-sycophantic. it should test whether affection, hostility, authority, grievance, or self-interest is contaminating judgment.
sessions are administratively private. ordinary users and unrelated subsystems receive no transcript. authorized main administration may access sessions. minimum necessary derived state may flow downstream.
dependency sovereignty doctrine
savant should own every strategically important capability contract even when external machinery remains underneath it.
classify dependencies as native, facade, adaptable/vendorable, or foundational.
do not pursue zero dependencies as an arbitrary target. pursue zero architectural dependence on replaceable third-party semantics.
proprietary replacement process
for each candidate external capability:
identify exact current consumers and behavior.
inspect savant for an equivalent primitive or incomplete implementation.
identify dependencies and dependents.
classify retain/facade/adapt/replace.
if replacing, define the savant capability contract first.
implement using existing reusable savant primitives where possible.
preserve behavior required by consumers.
preserve lineage, provenance, license facts, and antecedent techniques.
provide fallback/compatibility where required.
migrate dependents reversibly.
remove the external dependency only after verified non-use.
proprietary replacement naming
this rule applies only to savant-owned replacements/equivalents of external libraries or external-library capabilities.
the replacement receives an obscure real word that:
is unrelated to programming/system terminology;
does not literally describe the capability;
is unrelated to the external library name;
has never been used in savant;
produces a unique first-five-letter stem;
is unlikely to collide with future system terminology.
the artifact is named <first-five>-sav plus its normal extension where applicable.
the full obscure word remains canonical metadata. no name is admitted until current savant lexicon/filesystem collision checking passes.
existing savant-native scripts and applications keep their established names.
replacement metadata
every proprietary replacement must expose canonical obscure word, five-letter stem, artifact name, capability identity, contract, external antecedents, classification, authority, version, lineage, provenance, dependencies, dependents, compatibility surface, equivalence requirements, intentional divergences, license provenance, security considerations, fallback, migration state, and supersession history.
implementation ownership
envoy owns moral-self/persona semantics.
opus owns provider/model/api execution used by psychologist or moral jury.
palaver owns conversation.
niche owns task governance.
coda owns durable authorized mutation where established.
no new subsystem may duplicate those authorities.

migrate dependents.
validate one focused functional path and one integration path per bounded task.
completion conditions
moral-self completion requires live orobouros integration, stable provider-independent identity, deterministic fallback, preserved authority, privacy boundaries, provenance, replayability, and no regression to existing persona/conversation behavior.
dependency-sovereignty completion requires an authoritative inventory, classifications, savant-owned seams for strategically important replaceable semantics, and provenance-bearing collision-safe proprietary replacements where replacement is justified.
