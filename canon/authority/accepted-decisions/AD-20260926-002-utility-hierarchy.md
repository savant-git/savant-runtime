# accepted decision: utility hierarchy

status: accepted
accepted: 2026-09-26
authority: current user directive
scope: savant utility composition
implementation_state: authority accepted; propagation pending

## decision

the canonical savant utility hierarchy is:

glyph → iota → spasm → vagary → epiphany → tactic → artifice → agenda → oeuvre

the hierarchy contains exactly nine ordered utility levels.

## levels

### glyph

glyph is the atomic utility level.

it is the smallest canonical unit from which utility composition can emerge.

ordinal: 0

### iota

iota is the first composition above glyph.

an iota composes glyph-level utility while remaining below independently emergent utility behavior.

ordinal: 1

### spasm

spasm is the first discrete emergence of utility behavior from lower composition.

ordinal: 2

### vagary

vagary is utility whose composed behavior has developed a distinguishable direction, tendency, or variation beyond an isolated spasm.

ordinal: 3

### epiphany

epiphany is utility whose lower behaviors resolve into a coherent functional conception.

ordinal: 4

### tactic

tactic is utility organized into a reusable method for accomplishing a bounded functional purpose.

ordinal: 5

### artifice

artifice is coordinated tactical utility whose composition produces a larger independently coherent capability.

ordinal: 6

### agenda

agenda is coordinated artifice-level utility organized toward a broader functional purpose.

ordinal: 7

### oeuvre

oeuvre is the highest canonical utility level.

an oeuvre is a unified body of utility whose lower agendas and compositions emerge as a coherent highest-order capability.

ordinal: 8

## composition law

higher utility levels emerge through composition of lower utility instances.

canonical substance must not be duplicated merely because it participates in a higher utility level.

a higher utility instance references, composes, parameterizes, attaches, or projects lower canonical substance wherever composition or reference is sufficient.

utility level describes emergent functional composition.

utility level does not independently establish identity hierarchy level, programming-edifice level, authority, ownership, lifecycle, provenance, lineage, or physical storage size.

## orthogonality

the utility hierarchy is distinct from the identity hierarchy.

the utility hierarchy is distinct from the programming-edifice hierarchy.

the programming-edifice hierarchy remains:

glyph → line → segment → snippet → script → engine → subsystem → system → application

shared use of glyph does not collapse these hierarchies into one hierarchy.

glyph may participate as the atomic primitive where applicable while each hierarchy describes a different compositional dimension.

## zero-duplication rule

canonical utility substance exists once.

higher utility composition must prefer instances, references, typed segues, attachments, parameterization, and deterministic projection over duplicated substance.

zero duplicated substantive bytes is the architectural objective.

representation required for identity, addressing, lineage, provenance, relationships, or deterministic reconstruction is not itself prohibited duplication.

## terminology

the following utility-level terms are canonical savant-owned terminology:

- glyph
- iota
- spasm
- vagary
- epiphany
- tactic
- artifice
- agenda
- oeuvre

the previously accepted marine utility vocabulary is superseded as the active utility hierarchy.

historical evidence using the superseded vocabulary remains historical evidence and must not be destructively rewritten merely to conceal lineage.

new implementation must use the canonical hierarchy unless compatibility with historical implementation requires an explicit compatibility projection.

## uniqueness

before acceptance, the seven newly selected post-iota terms were checked against the current savant source baseline for conflicting savant terminology.

the accepted new terms are:

- spasm
- vagary
- epiphany
- tactic
- artifice
- agenda
- oeuvre

## classification rule

existing implementation must not be mechanically reclassified by preserving the ordinal of a superseded utility term.

classification under this hierarchy must follow the semantic utility level actually exhibited by the implementation.

therefore an implementation previously labeled current, tide, surge, torrent, sea, or another superseded utility level does not automatically inherit the replacement term at the same ordinal.

## propagation

this accepted decision requires eventual propagation to:

- lexicon
- authoritative graph projections
- utility-aware runtime implementation
- sieve configuration composition
- documentation that presents the active utility hierarchy

propagation must preserve historical lineage and compatibility where required.

## authority effect

this decision changes savant terminology and utility-composition authority.

it does not by itself assert that every existing implementation has already been migrated.

it does not by itself assign sieve, configuration, or another existing component to a particular utility level.

those classifications require implementation evidence against the semantic definitions above.
