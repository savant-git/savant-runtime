# accepted decision: three primary edifices

status: accepted
accepted: 2026-09-28
authority: current user directive
scope: savant primary architectural edifices

## decision

savant has exactly three primary architectural edifices:

1. identity
2. utility
3. programming

no additional primary architectural edifice exists unless established by later accepted authority.

## identity edifice

the identity edifice expresses what kind of thing an instance is.

existing accepted identity-edifice substance, levels, lineage, dependencies, dependents, and projections remain authoritative except where explicitly superseded by later accepted authority.

older references to the canonical identity architecture as an identity hierarchy are superseded as active terminology by identity edifice.

## utility edifice

the utility edifice expresses emergent functional composition.

the accepted utility sequence remains:

glyph
→ iota
→ spasm
→ vagary
→ epiphany
→ tactic
→ artifice
→ agenda
→ oeuvre

the substance and ordering established by earlier accepted utility authority remain in force.

older references to this canonical architecture as the utility hierarchy are superseded as active terminology by utility edifice.

## programming edifice

the programming edifice expresses programming composition.

existing accepted programming-edifice substance, levels, lineage, dependencies, dependents, and projections remain authoritative except where explicitly superseded by later accepted authority.

older references to the canonical programming architecture as programming hierarchy, programming-composition hierarchy, or equivalent architectural hierarchy terminology are superseded as active terminology by programming edifice.

## orthogonality

identity, utility, and programming are independent compositional dimensions.

classification in one edifice does not establish classification in another.

an instance may simultaneously occupy positions in all three edifices.

shared primitives, names, or levels do not collapse the edifices into one architecture.

## edifice terminology boundary

edifice is reserved for the three canonical savant architectural edifices:

- identity
- utility
- programming

ordinary descriptive uses of hierarchy remain hierarchy when they describe ordering, precedence, nesting, prominence, dependency, authority, visual organization, typography, motion, information structure, or another relationship that is not one of the three architectural edifices.

therefore ordinary phrases such as:

- visual hierarchy
- motion hierarchy
- typographic hierarchy
- information hierarchy
- authority hierarchy

do not establish additional savant edifices and must not be mechanically renamed.

## migration law

migration from obsolete architectural hierarchy terminology to edifice terminology is semantic rather than global lexical substitution.

a term may be migrated to edifice only when it denotes one of:

- identity edifice
- utility edifice
- programming edifice

historical evidence must not be rewritten merely to modernize terminology.

accepted decisions remain immutable.

historical backups, captured states, migration evidence, provenance records, and lineage records retain the terminology that existed when they were created.

current implementation, current projections, and current documentation must use edifice where one of the three canonical architectural edifices is intended.

## compatibility

compatibility surfaces may preserve obsolete identifiers only when necessary to prevent breakage of a verified dependent.

such compatibility surfaces do not establish current terminology or current authority.

obsolete compatibility identifiers must not be projected as canonical names.

## supersession

this decision supersedes, only where inconsistent:

- earlier active terminology that calls the canonical identity architecture a hierarchy;
- `ad-20260926-002-utility-hierarchy` terminology that calls the canonical utility architecture a hierarchy;
- earlier active terminology that calls the canonical programming architecture a hierarchy or programming-composition hierarchy;
- earlier assertions that the three primary edifices are identity, scale, and content.

the historical accepted decisions themselves remain unchanged.

their architectural substance remains authoritative except where directly contradicted by this decision or later accepted authority.

## projection requirement

current authoritative projections must converge on exactly these primary edifice identifiers:

- identity
- utility
- programming

a projection that presents another primary edifice is noncanonical unless supported by later accepted authority.

## preservation requirement

implementation of this decision must preserve:

- behavior;
- compatibility where required;
- identity;
- lineage;
- provenance;
- dependencies;
- dependents;
- deterministic replay;
- immutable accepted decisions;
- historical evidence.

no implementation may satisfy this terminology decision by destructively rewriting historical authority or provenance.
