## 1. Purpose

This constitution defines the canonical structural laws governing Savant.

It establishes:

1. hierarchy containment;
2. universal instances;
3. Rubrics;
4. Cabals;
5. Kindred;
6. moods;
7. slots and attachments;
8. task guidance and the Masterplan;
9. projection, validation, and migration.

It does not move existing files.

It does not establish authority from filesystem presence alone.

It governs structural classification and all subsequent implementation.

## 2. Authority and supersession

This constitution preserves:

- the accepted authority precedence;
- immutable accepted decisions;
- the universal instance model;
- the segue-placement rule;
- the nine-level identity hierarchy;
- verified existing behavior;
- canonical substance stored once;
- files treated as projections unless expressly authoritative;
- lineage, provenance, and history;
- reversible migration.

This constitution establishes the canonical nine-level content hierarchy:

1. character;
2. line;
3. snippet;
4. script;
5. module;
6. service;
7. application;
8. suite;
9. estate.

Any prior seven-level content hierarchy is historical and superseded.

No active constitutional provision may describe the canonical content hierarchy
as containing seven levels.

## 3. Nine structural mechanisms

Savant separates nine structural concerns:

| Concern | Canonical mechanism |
|---|---|
| Containment | Hierarchy and segue |
| Composition | Instances |
| Program implementation | Rubric |
| Shared implementation | Cabal |
| Relationships | Kindred |
| Transformation | Mood |
| Capability attachment | Slot |
| Task guidance | Niche task graph and Masterplan |
| Materialized view | Projection |

These mechanisms are related through Kindred but remain semantically distinct.

## 4. Universal instance law

Every Savant object is an instance.

Every instance may compose other instances.

All hierarchy levels use the same universal instance model.

No hierarchy type receives a separate storage architecture merely because its
semantic function differs.

Every canonical instance must expose or reference:

1. stable identity;
2. archetype;
3. hierarchy kind;
4. authoritative parent;
5. composition;
6. Kindred edges;
7. Rubric bindings;
8. Cabal bindings;
9. mood bindings;
10. slots;
11. attachments;
12. parameters;
13. lineage;
14. provenance;
15. dependencies;
16. authority state;
17. schema version;
18. immutable history.

Canonical instance substance is substantiated exactly once.

Consumers reference canonical instances rather than copying their substance.
