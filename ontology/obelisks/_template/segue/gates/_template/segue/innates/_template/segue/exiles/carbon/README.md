# carbon exile

status: active canonical exile.

## singular purpose

carbon turns consented source material into stable, normalized, composable embodiment.

carbon owns the transformation boundary between source material and reusable embodiment projections.

## authority

carbon owns:

- embodied simulation ingress
- source packet normalization
- substrate formation
- embodiment stabilization
- embodiment projection
- embodiment packet formation
- embodiment packet auditing
- carbon-owned lineage projection
- carbon-owned provenance projection
- carbon-owned consent projection

carbon does not acquire authority over a represented identity by processing it.

external execution backends retain their own execution authority.

## primary application

avatar forge is carbon's current embodied simulation application.

avatar forge is manifest-first and consent-gated.

its application shell and carbon semantics remain stable when reconstruction, rendering, rigging, voice, or other execution backends change.

## composition

carbon stores and exposes reusable embodiment projections.

consumers compose those projections by reference whenever reference is sufficient.

carbon projections do not duplicate source authority.

derived structures remain rebuildable whenever their authoritative primitives remain available.

## invariants

- identity-bearing ingress requires explicit consent.
- source identity authority remains with the source.
- normalization preserves source references.
- lineage is preserved.
- provenance is preserved.
- consent state is preserved.
- attached backends are replaceable.
- backend attachment does not transfer authority.
- consumer invocation does not transfer carbon authority.
- projections do not become authoritative source primitives merely by being materialized.
- lower-level substance is referenced rather than duplicated when composition suffices.
- carbon-owned terminology, identifiers, paths, and projections remain lowercase unless external compatibility requires otherwise.

## structure

carbon is self-contained and recursively extensible through:

- apps
- runtime
- registry
- canon
- authority
- lineage
- graph
- api
- tests
- docs
- observatory
- segue
- composition
- interface
- introspection

no hidden external structure defines carbon's identity, authority, lineage, registry, or graph projection.
